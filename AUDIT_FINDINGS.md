# QEComp Plan-vs-Implementation Audit

**Scope:** Full cross-check of `tm_update_plan.md` (v3.0) against the merged `qecomp-rewrite` branch (`backend/`, `frontend/`, `alembic/`, `k8s/`, `docs/`) as of commit `d6be1bf`. This is a findings report only — nothing in the codebase was changed as part of this audit.

**Method:** Six parallel research passes, each covering a distinct plan area, cross-checked against actual source (routers, models, migrations, frontend pages/hooks, k8s manifests, tests, docs). Findings below are deduplicated and ranked: **Missing entirely > Stubbed/fake > Diverges from spec > Correct but poor quality**.

## 3. Diverges from spec

| # | Plan citation | Current state | Suggested fix |
|---|---|---|---|
| 3.1 | §5.12 — "The predicted score is never shown to anyone except internally. Only the [`high_potential`] flag appears [on browser-facing surfaces]." | **Real, unenforced leak, HIGH severity.** The purpose-built `/ws/prompter` and `/ws/overlay` dispatch paths correctly strip `predicted_red`/`predicted_blue` down to a bare `high_potential` bool. But `ConnectionManager._dispatch` in `backend/routers/ws.py` (~line 165-168) unconditionally `broadcast_all(data)`s **every raw event verbatim** to `/ws/events` *before* any filtering — and `/ws/events` is consumed directly by Dashboard, MatchControl, FieldMonitor, Timers, AuditLog, and Integrations pages. This means the full predicted scores reach every one of those browser connections regardless of whether the React UI renders them. No test asserts these fields are stripped from `/ws/events` (only that Postgres never receives them — a narrower guarantee). | In `ConnectionManager._dispatch`, redact `predicted_red`/`predicted_blue` from `match_prediction` events (or exclude the event type) before `broadcast_all`, matching what the prompter/overlay dispatch path already does correctly. |
| 3.2 | §13/§11 — `POST /api/v1/integrations/{entity_id}/service/{service}` permission should be domain-specific only (`vfx:control`/`video:control`/`audio:control`/`tm:control`, "varies by integration") | The router **also** unconditionally requires `integrations:read` via `Depends()` before the domain-specific check runs. Per the seeded role mappings (`qecomp-video` group has `video:control` but *not* `integrations:read`), **the `qecomp-video` role cannot call ATEM/OBS services at all** — the very capability the plan assigns it. Real functional/RBAC bug, not a documentation issue. | Remove the blanket `integrations:read` dependency from `call_integration_service`; rely solely on the resolved domain-specific permission already checked in the function body. |
| 3.3 | §5.10, §13 — "Start Countdown" gated on `prompter:control`; only EMCEE can trigger it | The REST endpoint (`POST /timers/{entity_id}/start`) correctly requires `prompter:control`. But the WebSocket `start_countdown` message handler in `ws.py`'s `ws_prompter` — which is what the actual iPad page uses — only validates the HMAC teleprompter token, **not** the permission. Anyone with the (obscurity-based, never-expiring-until-rotated) teleprompter link can start the countdown regardless of RBAC role. | Require session/API-key-based `prompter:control` check (in addition to the HMAC token) before honoring `start_countdown` over the WS. |
| 3.4 | Appendix B.2 (marked CRITICAL — "do not substitute alternatives") — React 18 + Vite 5 + React Router v6 | Installed versions are **React 19.3.0, Vite 8.3.0, react-router-dom 7.18.3** — one or two majors ahead on all three pinned packages. | Pin down to the specified majors, or get explicit sign-off to update the plan's version pins (behavior appears compatible so far, but this violates an explicitly "critical, no substitution" constraint). |
| 3.5 | §12 Match Control — "Queue Skills (dropdown)", "Audience Display selector (dropdown of TM display modes)" | Both are free-text `Input` fields, not dropdowns populated from a known list/enum. | Replace with `<Select>` components once a skills-list/display-mode source is available. |
| 3.6 | §12 Teams — "Search/filter by team number, name, division" | Filter only matches `team_number`; name/division are not filterable. | Extend the filter predicate. |
| 3.7 | Appendix A.10 — Dashboard should show a distinct "Redis unavailable" **warning banner** | Backend degradation logic is correct (no crash, `/readyz` reports "degraded" rather than 503 on Redis-only failure). Frontend only shows a plain `Redis: unreachable` status line inside the Cluster Status card — not a warning-banner treatment like the properly-implemented `ReconnectingBanner` (A.14). | Add a dedicated banner component (mirroring `ReconnectingBanner`) triggered by `readyz.redis === false`. |
| 3.8 | §C.7.3 (plan's own factual premise) — describes `obs-websocket-py` v1.x as "async-native" | The installed library is actually fully synchronous. The code correctly recognizes this and wraps every OBS call in `asyncio.to_thread()`, exactly like the ATEM integration — documented inline with the reasoning. This is the code being *right* and the plan being wrong. | No code fix needed; flag back to whoever maintains the plan so §C.7.3's OBS section gets corrected. |
| 3.9 | Appendix A.1/A.15 — OIDC must be provider-configurable via standard discovery | Discovery, JWKS, and `OIDC_GROUPS_CLAIM` are all genuinely configurable and provider-agnostic — correct. One soft gap: the requested OAuth `scope` string is hardcoded to `"openid profile email groups"` rather than being configurable like the groups claim is. Works for both Authentik and Authelia (the only two providers this has touched), but isn't guaranteed for an arbitrary generic OIDC provider. | Consider an `OIDC_SCOPES` env var for full parity with `OIDC_GROUPS_CLAIM`'s configurability. | 3.10 | Appendix C.3 (component prop rule — "Props should be IDs... not full entity objects") | `IntegrationStatusChip` takes a full `IntegrationInstance` object as a prop from 4 call sites rather than an `entityId` + internal fetch. | Minor; either accept the pragmatic deviation (parent already fetched the list) or refactor to take an ID. |
| 3.11 | Appendix C.8.4 ("never merge REST + WS data into a single derived object") | `IntegrationStatusChip` does `liveStatus ?? integration.status` — a narrow, documented fallback (bridges the gap before the first WS event arrives), not a full object-spread merge. | 3.12 | §14 Test Stack table — `fakeredis`/mocks specified so "no real Redis needed" | Several suites (RBAC's API-key path, leader election, timer, predictor, scraper) instead connect to a real Postgres/Redis on non-default ports and `pytest.skip()` if unreachable. ## 5. Verified correct — no action needed

For completeness, these previously-flagged or plausible-gap areas were checked and found to genuinely match the plan:

- **Leader election** (§3.1): lock value is `<pod_ip>:<port>`, split-brain teardown-before-release, exponential backoff capped at 5 min — all correct.
- **Dynamic module hot-reload** (§3.2): `config_change` pub/sub diffing, live tear-down/spin-up with no restart — correct.
- **Integration interface consistency** (§9, C.2): all 5 domains implement exactly `setup/teardown/call_service/get_state` — no drift.
- **Async discipline** (C.7): ATEM and ZerOS correctly wrap sync libraries in `asyncio.to_thread()`; no banned blocking patterns found across any of the 5 integrations.
- **All 8 of §3.7's VEX TM known-issue fixes**: confirmed present and correct in `vex_tm/integration.py`.
- **§8 schema-to-code**: every one of the 13 tables has a matching Alembic migration and SQLAlchemy model; all but `audit_log` (see 1.6) have router coverage (some nested under other resources, which is legitimate).
- **§11 API endpoint audit**: every endpoint in every table (Health, Auth, Integrations, Automations & Scripts, Timers, Overlays, Teams, Settings & Users, WebSocket channels) exists with the correct path and permission, except the two gaps already listed (1.5, 1.7) and the one RBAC bug (3.2).
- **Automation engine core** (§5.8, §10, A.7, B.6): retry-once-then-continue, YAML "Validate" endpoint (syntax-only, no execution), `SandboxedEnvironment` Jinja2 (real security control, not just a comment), tag targeting via `asyncio.gather` with per-candidate `target_filter` evaluation, and `delay`/`repeat`/`script` action types — all correctly implemented and backed by genuine unit tests, not just docstrings.
- **Scraper** (§5.11): auto-creation on `fieldMatchAssigned` with existing-profile dedup check, fetches from both TM and Robot Events APIs, 24h Redis cache at the correct key, computes qual avg/high/low and OPR inputs — correct.
- **Frontend TypeScript strict mode + zero `any`**: independently re-verified with a full-repo grep — the prior wave's "zero any" claim is **true** (0 real occurrences, only false-positive substring matches in comments).
- **Frontend module boundaries & REST/WS data separation** (C.3, C.8): no raw `fetch()` in pages/components, no cross-layer imports, no `queryClient.setQueryData()` from WS handlers, `useCacheSync()` correctly implements invalidate-only — clean.
- **Design system** (Appendix D): CSS variables and `.vmd-*` classes match closely; one disclosed, justified deviation (dropped `width: 100%` on navbar to fix an overflow bug).
- **k8s/ingress.yaml**: genuinely uses `traefik.io/v1alpha1` `IngressRoute`, not a plain `Ingress` — correct per Appendix A.9.
- **k8s/deployment.yaml**: 2 replicas, RollingUpdate, required podAntiAffinity, alembic init container, correct liveness/readiness probes, `uvicorn --workers 1` — all correct per §15/Appendix B.1.
- **docs/API.md**: not stale — routers have been stable since before the doc was last regenerated; endpoint counts reconcile.
- **docs/AUTHENTIK_SETUP.md**: exists and is complete per Appendix A.15.
- **Timer "Match Running" state machine** (Appendix A.3): correct 4-phase transition (idle → countdown → match-running count-up → match-complete on `matchStopped`).
- **Teleprompter HMAC token validation & regeneration** (Appendix B.8): correct — nonce-based rotation invalidates old tokens as specified.
- **Default RBAC group→permission seed data** (§13): all 6 groups seeded correctly and match the plan's table verbatim (the mismatch in 3.2 is a router bug, not a seed-data bug).
- **WebSocket reconnect UX** (Appendix A.14): correct exponential backoff (1s→2s→4s→8s→16s→30s cap) with a reconnecting banner.
