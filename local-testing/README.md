# Local testing stack (Traefik + Authelia)

Not real infrastructure — that's `k8s/` (Traefik IngressRoute CRD on the
actual k3s cluster, per plan Appendix A.9). This is a throwaway local dev
stack so you can exercise the real OIDC login flow (`backend/routers/auth.py`)
against a real OIDC provider instead of only the `/admin_login` emergency
path, and see the app behind a reverse proxy at real-looking hostnames
instead of bare `localhost:PORT`.

`*.vex.localhost` resolves to `127.0.0.1` automatically (`.localhost` is
reserved for loopback, RFC 6761) — no `/etc/hosts` edits needed.

## Setup

```bash
./local-testing/setup.sh
docker compose -f compose.yml -f local-testing/docker-compose.proxy.yml up -d
```

That also brings up `compose.yml`'s `app` service (the full stack built
from this repo's `Dockerfile`), along with its `migrate` and `bucket-init`
one-shot dependencies — Postgres migrations and MinIO bucket creation both
happen automatically, no manual `alembic upgrade head` or MinIO console
click-through needed on a clean `docker compose down -v`.

Then run the backend and frontend yourself (they run on the host, not in
this compose file — Traefik reaches them via `host.docker.internal`):

```bash
# backend/.env (or exported env vars) needs:
#   OIDC_ISSUER_URL=https://authelia.vex.localhost
#   OIDC_CLIENT_ID=qecomp
#   OIDC_CLIENT_SECRET=<printed by setup.sh>
#   OIDC_GROUPS_CLAIM=groups
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --proxy-headers --forwarded-allow-ips='*'

cd frontend && npm run dev -- --host 0.0.0.0
```

The backend's own outbound HTTPS calls to Authelia (OIDC discovery + token
exchange) need to trust `traefik/certs/vex.localhost.crt` — `setup.sh`
prints the one-liner to find your venv's certifi bundle; append the cert
to it.

## Routes

| Host | Goes to |
|---|---|
| `https://vex.localhost` | Vite dev server, which itself proxies `/api`, `/auth`, `/ws`, etc. to the backend |
| `https://api.vex.localhost` | Backend directly (OpenAPI docs at `/docs`, curling the API without the SPA) |
| `https://authelia.vex.localhost` | Authelia's login portal |
| `https://traefik.vex.localhost/dashboard/` | Traefik's dashboard, protected by Authelia forward-auth |

Login: `admin` / whatever `setup.sh` printed (also in
`authelia/.admin_password_plaintext`, gitignored). That account is in the
`qecomp-admin` Authelia group, seeded in the app's `role_permissions` table
with the wildcard permission.

## Why a real cert instead of Traefik's auto-generated one

Traefik auto-generates a self-signed default certificate with no SANs,
which fails hostname validation for any client that actually checks
certs — including the backend's own outbound calls to Authelia for OIDC
discovery/token exchange. `traefik/dynamic/tls.yml` points Traefik at a
proper self-signed cert (SAN: `vex.localhost`, `*.vex.localhost`) instead,
generated by `setup.sh`. Browsers still show a "not secure" warning for
any self-signed cert; accept it once per host.

## Notes

- Authelia's ID token is minimal by default (no `groups`/`email`/
  `preferred_username`) unless a `claims_policy` embeds them — see the
  `claims_policies` block in `authelia/configuration.yml`. Without it,
  every OIDC login resolves to zero permissions and the UI shows the raw
  `sub` UUID instead of a username.
- `docker-compose.proxy.yml` bind-mounts `authelia/*.pem`/`.jwt_secret`/etc
  directly (not Docker's `secrets:` construct) so they can land at
  arbitrary container paths — Authelia's env-var config overrides only
  support `_FILE` suffixes for a fixed set of top-level keys, not
  per-list-item fields like `clients[0].secret`, so the OIDC client secret
  digest is a plain (hashed, not plaintext) value in `configuration.yml`
  instead.
